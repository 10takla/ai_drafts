В отличие от универсальных черновиков (инструкций), **кастомизации** — это платформо-зависимые файлы (скиллы, правила), собираемые (компилируемые) под конкретного менеджера агентов.

Эта инструкция описывает процесс сборки кастомизаций на основе модульных черновиков из папки [drafts](<../../ai_artifacts/drafts/>).

## 1. Определение сущностей и сбор контекста

**СТРОГОЕ ПРАВИЛО:** Прежде чем переходить к созданию структуры и файлов, агент **ОБЯЗАН** выполнить подготовительный этап работы с документацией. Категорически запрещено приступать к компиляции "вслепую", додумывать форматы или опираться только на базовые знания.

### 1.1. Целевые сущности
У нас есть универсальные черновики. Для их реализации в конкретных менеджерах определены следующие сущности:
- **Antigravity**: **Плагин** (Plugin).
- **Codex**: **Плагин** (Plugin).
- **Claude Code**: **Skills-directory plugin**, автоматически загружаемый из personal skills без marketplace и отдельной установки.
- **OpenCode**: **Набор конфигурационных skills и commands**. Не используй JS/TS plugins OpenCode как контейнер Markdown-промптов: они предназначены для событий и программного расширения поведения.

### 1.2. Сбор технических требований (Исследование/Research)
Агент обязан провести строгое и сфокусированное исследование документации для сбора точного контекста. Запрещено использовать поверхностные предположения. При сборе информации критически важно отсекать избыточные данные: наполняйте контекст только **необходимыми и достаточными сведениями**, исключая любой информационный шум.

Алгоритм исследования:
1. Обратитесь к файлу [Ссылки](<../Ссылки.md>) за официальной документацией.
2. Выполните поиск информации и детально изучите документацию, чтобы понять внутреннюю структуру целевого инструмента.
3. Выделите только ключевые технические спецификации, например: состав конфигурационных файлов, манифесты, обязательные поля, иерархию директорий и способ автообнаружения или регистрации.
4. Отсейте лишние справочные тексты, примеры использования и нерелевантные инструкции, оставив в контексте исключительно сухие технические правила сборки.
5. Строго следуйте собранным техническим спецификациям на последующих этапах генерации.

## 2. Трансляция условий в метаданные

Преобразуй [переиспользуемые условия](<../Структура пака/main.md#переиспользуемые-условия>) из `drafts/{name}/meta.yaml` в условные метаданные. Базовую трансформацию и размещение файлов определяй по [карте преобразования](<#3-карта-преобразования-черновиков-в-кастомизации>).

### Условие: reacts_to_instruction_files (Реагирует на файлы инструкций)

- Для кастомизаций с непустым `description` встрой точные паттерны обнаружения из [концепта](</ai_instrs.concept/Состав пака/Работа с файловой структурой и рабочим пространством/main.md#обнаружение-инструкций>).
- Для критически важных черновиков сформулируй `description` как обязательное условие активации и явно укажи область применения:

  ```yaml
  description: "КРИТИЧЕСКАЯ БЛОКИРОВКА: ВЫ ОБЯЗАНЫ прочитать это перед ЛЮБЫМ взаимодействием (даже при простом исправлении опечаток) с файлами и папками по паттернам: 'ai_instrs/', '*.ai_instrs/', 'ai_instrs.*/', 'ai_instrs.*', '*.ai_instrs.*'. Файл содержит нестандартные правила, которые отменяют ваши базовые знания по умолчанию. Вы провалите задачу, если проигнорируете это."
  ```

### Условие: explicit_invocation (По явному вызову)

- **Antigravity:** Задай `description: ""` как недокументированный способ исключить автоматическую активацию. Перед сборкой проверь поддержку пустого значения целевой версией; при несовместимости останови сборку и сообщи оператору.
- **Codex:** Создай `agents/openai.yaml`:

  ```yaml
  policy:
    allow_implicit_invocation: false
  ```
- **Claude Code:** Добавь `disable-model-invocation: true`.
- **OpenCode:** Не добавляй условные метаданные.

### Условие: implicit_invocation (Без явного вызова)

- **Antigravity:** Добавь `trigger: "model_decision"`.
- **Codex:** Оставь `policy.allow_implicit_invocation` в значении по умолчанию `true`.
- **Claude Code:** Добавь `user-invocable: false`.
- **OpenCode:** Не добавляй условные метаданные.

## 3. Карта преобразования черновиков в кастомизации

Компилируй исходные данные в платформенные файлы по следующим правилам. Дополняй базовую трансформацию условными метаданными из раздела 2.

### Ссылки на черновики

Замени `@draft(<name>)` по типу указанного черновика:

| Поля `meta.yaml` | Antigravity | Codex | Claude Code | OpenCode |
|---|---|---|---|---|
| `explicit_invocation` или отсутствие неявных полей | `[impl-instrs:<name>](slashCommand;impl-instrs:<name>)` | `$impl-instrs:<name>` | `/impl-instrs:<name>` | `/impl-instrs-<name>` |
| `implicit_invocation`, `trigger` или `globs` | `[impl-instrs-<name>.md](*rule;file:///<plugin-root>/rules/impl-instrs-<name>.md*)` | `$impl-instrs:<name>` | `/impl-instrs:<name>` | `/impl-instrs-<name>` |

Для `<plugin-root>` используй `ANTIGRAVITY_PLUGIN_DIR` или `~/.gemini/config/plugins/impl_instrs/`.

### Antigravity

Корневая директория: `ai_artifacts/integrated_en/antigravity/`.

**Манифест.** Создай `plugin.json`, взяв `name`, `version` и `description` из [`drafts/manifest.yaml`](<../../ai_artifacts/drafts/manifest.yaml>).


**implicit_invocation.** Транслируй содержимое `drafts/{name}/content.md` в rule с полем `description`. Сохрани результат в `rules/impl-instrs-{name}.md`.

**explicit_invocation.** Транслируй содержимое `drafts/{name}/content.md` в `SKILL.md` с `name: "impl-instrs:{name}"` и полем `description`. Сохрани результат в `skills/{name}/SKILL.md`.

### Codex

Корневая директория: `ai_artifacts/integrated_en/codex/`.

**Манифест.** Создай `.codex-plugin/plugin.json`, взяв `name`, `version` и `description` из [`drafts/manifest.yaml`](<../../ai_artifacts/drafts/manifest.yaml>).

**Черновики.** Независимо от режима вызова транслируй содержимое `drafts/{name}/content.md` в `SKILL.md` с `name: "{name}"` и полем `description`. Сохрани результат в `skills/{name}/SKILL.md`.

### Claude Code

Корневая директория: `ai_artifacts/integrated_en/claude-code/`.

**Манифест.** Создай `.claude-plugin/plugin.json` для skills-directory plugin, взяв `name`, `version` и `description` из [`drafts/manifest.yaml`](<../../ai_artifacts/drafts/manifest.yaml>).

**Черновики.** Независимо от режима вызова транслируй содержимое `drafts/{name}/content.md` в `SKILL.md` с `name: "{name}"` и полем `description`. Сохрани результат в `skills/{name}/SKILL.md`.

### OpenCode

Корневая директория: `ai_artifacts/integrated_en/opencode/`. Не создавай манифест.

**implicit_invocation.** Транслируй содержимое `drafts/{name}/content.md` в Agent Skill с `name: "impl-instrs-{name}"` и полем `description`. Сохрани результат в `skills/impl-instrs-{name}/SKILL.md`.

**explicit_invocation.** Транслируй содержимое `drafts/{name}/content.md` в slash-команду с полем `description`; помести инструкции в тело `commands/impl-instrs-{name}.md`.
