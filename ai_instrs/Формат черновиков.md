## Структура директории

```text
<draftsDir>/
  manifest.yaml
  <группа>/
    <название черновика>/
      meta.yaml
      content.md
      <дополнительные файлы и директории>?
```

Промежуточных групп может быть любое количество. Директория с `meta.yaml` и `content.md` является листовым черновиком.

## Псевдосхема

Обозначения:

- `?` — необязательное поле;
- `*` — ноль или более значений;
- `|` — один из вариантов.

```yaml
manifest.yaml:
  name: string         # Имя пака.
  version: string      # Версия пака в формате MAJOR.MINOR.PATCH.
  description?: string # Описание пака.

  custom_conditions?:                         # Фрагменты итогового description.
    <custom_condition>: string                 # Имя условия: фрагмент description.
```

```yaml
meta.yaml:
  description?: string # Когда и зачем применять черновик.

  conditions:                                      # Условия активации по порядку.
    - explicit_invocation | implicit_invocation    # Явный вызов | автоматическое применение.
    - <custom_condition>*                          # Имя условия из custom_conditions; его фрагмент входит в description.

  globs?: string | string[] # Шаблоны файлов, к которым относится черновик.
```

Ограничения:

- `name` содержит строчные латинские буквы, цифры и одиночные дефисы и задаёт имя пака;
- `conditions` содержит ровно один режим вызова;
- `explicit_invocation` и `implicit_invocation` зарезервированы и не используются как `<custom_condition>`;
- `trigger` не входит в формат черновика и формируется при компиляции.

## `content.md`

`content.md` содержит чистый текст инструкции без YAML frontmatter.

## Ссылки между черновиками

```text
@draft(<название черновика>)
```

Имя соответствует названию листовой директории. Сборщик преобразует ссылку в формат целевого менеджера.
